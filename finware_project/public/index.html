    About FinWare & ML Model

    How one classification model can support both spending behaviour and financial risk indicators.
    FINWARE INTELLIGENCE

    Turn transactions into smarter financial insights

    One shared Random Forest Classifier reads customer transaction patterns to estimate both spending behaviour and a financial risk indicator. A separate Isolation Forest flags unusual transactions.

    Shared classification model

    Random Forest

    Random Forest Classifier is used as the shared classification model for both customer spending behaviour and the financial risk indicator. It can capture non-linear relationships between spending amount, frequency, transaction patterns and financial behaviour without requiring a linear relationship between the features and the class.

    Problem typeMulti-class classification
    OutputsSpending: Low / Medium / High   •   Risk: Low / Medium / High
    Why Random Forest?Handles non-linear patterns, interactions and noisy transaction features well.
    InterpretabilityFeature importance can show which transaction patterns influence both outputs.
    Shared model benefitOne consistent feature set and classifier supports both behaviour and risk indicators.

    Anomaly detection model

    Isolation Forest

    Isolation Forest is used as the anomaly-detection model because transaction anomalies usually do not have reliable labelled examples. It isolates observations that are rare or substantially different from normal customer spending patterns, making it suitable for unusual amount, frequency and category behaviour.

    Hyperparameters

    ParameterValuePurpose
    n_estimators200Number of isolation trees
    contamination0.05Expected proportion of anomalous transactions
    max_samplesautoUses an appropriate sample size for each tree
    random_state42Reproducible results

    Synthetic evaluation

    Precision89.0%
    Recall86.0%
    F1-Score87.5%
    ROC-AUC0.92
    Why these metrics? Accuracy can be misleading for anomaly detection because anomalies are usually a small minority. Precision, recall, F1-score and ROC-AUC better describe how effectively unusual transactions are identified.

    Why classification for both spending and risk?

    FinWare is not trying to predict an exact rupee value. It needs to assign customers to meaningful categories. Therefore, multi-class classification is appropriate for both outputs. The same transaction-derived features can be used to classify spending behaviour and financial risk into Low, Medium and High categories, keeping the recommendation and risk views consistent. In an actual deployment, the Random Forest would be trained on labelled customer data; the values shown in this interface are synthetic because the original training notebook is unavailable.
